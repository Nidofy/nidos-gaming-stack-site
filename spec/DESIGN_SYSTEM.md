# Design System Spec

## 目标

建立适合个人独立游戏发布站的视觉系统。整体方向为极简、清晰、产品化、强视觉层级，适合展示游戏截图、视频、下载按钮和开发日志，同时保持长期扩展能力。

## 约束

- 可借鉴 apple.com 的产品展示气质，但不得复制其具体素材、图标、字体、布局切片或文案。
- 不做只适合单个游戏的视觉系统。
- 移动端体验必须优先考虑，首屏不能依赖桌面宽屏才成立。
- 不用未经授权的真实赛事、战队、选手、Dota/Valve/The International 视觉资产。
- 设计不应被单一色系完全支配；不同游戏可以有自己的 accent color，但站点品牌层应保持稳定。

## 推荐实现方式

- 使用 Tailwind CSS，结合 CSS custom properties 定义 token。
- 基础 token 包括：背景、前景、弱文本、分割线、主按钮、次按钮、强调色。每个作品可通过局部 `--color-accent` 提供克制的主题点缀色，但字号层级、行高、卡片圆角、边框、阴影和留白节奏必须在全站保持一致。
- 统一圆角与容器规范：主展示卡与大横幅使用 `rounded-[28px]`，常规信息卡与画廊图卡使用 `rounded-[24px]` 或 `rounded-[22px]`，配合 `border border-line bg-panel`；避免部分模块突兀使用直角小圆角（如 `rounded-lg` 黑框）或脱离全站排版的独立样式体系。
- 首页切换器同时容纳游戏与插件条目，所有条目的首屏摘要卡、下方预览区及底部全作品目录均遵循统一版式，切换标签时页面结构稳定、不发生剧烈跳变。
- 游戏详情页与插件详情页共享统一的标题字阶、信息摘要栏、特性网格、原比例/防裁切画廊、折叠 FAQ（`<details>`）与底部作品切换导航。
- 图标与按钮服务具体操作，不做装饰堆叠；作品自身的详情页主按钮不得指向当前页面自身。

## 后续 Codex 修改代码时必须遵守的检查项

- 视觉是否支持多个游戏，而不是只适配 TI 模拟器。
- 每个 section 是否有明确目的和层级。
- 移动端文字、按钮、媒体是否无重叠和溢出。
- 颜色对比度是否满足基本可读性。
- 是否使用原创或授权视觉资产。
- 是否避免过度卡片化和一次性装饰。
